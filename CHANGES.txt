Version 5.0.1 | 2026-11-19
- THE RELEASE-ROUND AUDIT CYCLE (two full passes: an initial fresh-codebase audit across eight independent subsystem reviews — main sketch, BLE/host-switch, serial API, screen/USB, input pipeline, persistence/timing, tests/CI/docs, and the LipSync Connect integration contract — plus a lead-authored review of every vendored library fork; then an adversarial round 2 over the fixes themselves and their cross-subsystem interactions, which found and closed five defects in the round-1 fixes and two latent pre-existing bugs they interacted with).
- BUILD REPRODUCIBILITY: build_firmware.yml now pins Adafruit TinyUSB Library@3.7.3 — the Seeed core 1.1.13 bundles TinyUSB 1.7.0, so the V5.0.0 release artifacts (built on a runner without the user-library copy) linked a DIFFERENT USB stack than every Maker-Guide/local build and than the bench-23-validated binary (~8.5 KB of linked code differ; the released image was never hardware-validated). CI now builds the exact configuration the documentation prescribes and the bench validated. The release also asserts the host suites' check counts (399/168 — a dropped test function can no longer ship green) and fails a workflow_dispatch fired on a tag ref with a named error.
- SAFE-MODE MENU FIX: safe mode no longer reads the menu action column while the safe menu is active. The menu column's STOP_MENU cells (an S2 3-8 s hold, or a sub-1-s press of both hub buttons) dismissed the safe menu, and with activateMenu refused in safe mode, the safe columns' open cells deliberately NOTHING, the timeout disabled and the serial open path refused, the device's only button-only Restart/Factory-Reset surface was unreachable until a power cycle. Round 2 closed the same class's second door: CH,1:4 (remote menu close) and closeMenu() itself now also refuse in safe mode, with the named ERROR line on the wire. Navigation is unchanged (the safe column carries the full NEXT/SELECT language).
- GAMEPAD USB RECOVERY: LSUSBGamepad::send() now mirrors the mouse's 4.9.1 latch — a not-ready endpoint is latched as an error episode only after 60 ms of wall-time persistence, and the episode's first latch hands off to usbCheckConnection() (in gamepad mode nothing else re-arms the check chain after a healthy boot, so a transient busy tick used to flash the No-USB page on a healthy device, and a real gamepad-mode USB outage after boot had no recovery driver at all). Round 2 also closed the latent instance-aliasing bug both USB classes carried: a never-begun interface's endpoint index defaults to 0 — the OTHER interface's — so a mode-mismatched remapped action (B1-B8 are mouse-column-admissible, LEFT_CLICK/DRAG gamepad-column-admissible) staged reports onto the wrong HID instance; both send paths are now no-ops until their own begin() registered them.
- HOST-LABEL DISCRIMINATOR: the Bluetooth switch confirm page draws the "name (XX)" target from the panel's left edge, and lsHostOledLabel now makes the name portion yield room for the " (XX)" suffix at tight caps (a full-length 17-char name used to fail the suffix's fit check and draw a BARE name — the discriminator, the only thing distinguishing two same-named hosts, silently dropped for the longest name class; wide callers are byte-identical).
- HID-WATCHDOG GRACE: the watchdog's grace anchor now ends at every CONNECT event via the vendored lib's peripheral connect callback (record-here-act-in-the-loop-task, the TinyUSB-callback shape). A drop→reconnect inside the 1 s poll gap (bench-documented for macOS) reuses the same handle number, so the handle-change re-key never fired and a fresh link could inherit an already-expired anchor and be cycled mid-CCCD-restore with zero grace.
- FORGET RESURRECTION GUARD: a forget (BT,2 / Hub menu) whose bond file is recreated by the stack's deferred bond save (a re-pair completing on the ada-callback thread while the forget executes) is re-applied on the following 1 s poll passes — bounded at 2 re-applications, named on the wire (the line states the cause disjunction the code cannot distinguish: a deferred bond save OR a deliberate in-window re-pair), and self-disarming after a 4 s absent window; a forget can no longer ack SUCCESS while silently undoing itself.
- SETTINGS INTEGRITY: the IZ/OZ setters validate and store through ONE flash read (the old two-read shape let a transient read failure between them validate the input against the fabricated default pair and persist it over the real one — SUCCESS on the wire, an inverted deadzone pair live, and both user values silently healed to defaults on the next load); sanitizeInputWindows' ordering verdicts compare against the next-higher window's POST-heal effective value (an out-of-range corrupt WL/WM no longer erases and persists 0 over a valid customized WS/WL); the CA,0 radius pass runs even when a stored corner failed its read gate (a boot double-fault could leave _inputRadius at 0 forever — a silently dead cursor with no wire trace).
- INPUT PRECISION: the deadzone magnitude map rounds the float magnitude before the int conversion (every in-band output sat up to 1 unit of 1024 low; a deflection just past the inner deadzone could round back to a zero output).
- SCREEN FIXES: the Bluetooth switch confirm page draws the "name (XX)" target from the panel's left edge with the label built to fit 21 glyphs — the (XX) discriminator (the page's whole point for same-named hosts) drew off-panel for 17-char names; the safe-mode hardware page renders missing-device names at size 1 so a third missing sensor is no longer off-panel; a Full Calibration start with no joystick sensor now draws "Joystick sensor missing" instead of freezing the confirm page for 2 s; a USB outage that begins while the Hub menu is open no longer latches the episode as "shown" (the page can paint once the menu closes), and a recovery that lands on an unpainted episode now paints the ready page instead of leaving a blank glass.
- SERIAL/API FIXES: pre-attach buffered boot diagnostics are protected by a byte watermark in the TX queue — the first host's prioritizeRequest() keeps the owed diagnostic prefix instead of clearing it when the host's SETTINGS beats the CDC drain (the safe-mode WARNING naming the missing devices could vanish exactly where it mattered); round 2 hardened the watermark's own bookkeeping (the enqueue extension no longer double-debits make-space drops — a prefix longer than the queue used to walk the watermark to zero and resurrect the original bug at exactly the overflow the buffer is sized against) and its make-space policy (a full queue sheds the NEWEST whole lines before touching the owed prefix; only an entirely-owed queue falls to the oldest-line drop); once-per-boot parse diagnostics are keyed per file and name the file (a /settings2.dat corruption is no longer silenced by an earlier /settings.txt failure); the EX,0 dump adds SIZE2:<size>/<budget> for the hard-band file.
- VENDORED-LIBRARY AUDIT (no changes required): the bounded Wire fork (bounded waits, bus-clear, PIN_CNF restore, rollover-safe deadlines), the Bluefruit52Lib fork (fault capture, the documented closed directed-adv trial), and the LPS2X/LPS35HW bounded-wait forks verified clean.
- INTEGRATION AUDIT (LipSync Connect): full serial-protocol enumeration app↔firmware (83 dispatch entries, all app shapes resolve; 5.0.0 refusal classes correctly classified), the DFU update pipeline verified end-to-end against CI's manifest format, settings ranges cross-checked, the app's 550-test suite passing, and the cross-repo protocol gate ALL-CHECKS-PASS. App-side hardening rides the app repo's own release train.
- VERIFICATION: host core suite 408/408 (23 new checks pin the TX-queue watermark semantics incl. the overflow/debt case and the tight-cap host label) and timer suite 168/168 under ASan/UBSan; production compile clean at --warnings all on the pinned core 1.1.13 WITH the pinned TinyUSB 3.7.3 (release-image sizes are now quoted from the pinned-configuration build — see the release manifest); the tracked source ZIP verified tree-identical by the release gate's entry-content rule; the LipSync Connect suite 553/553 with the cross-repo protocol gate ALL-CHECKS-PASS.
- BENCH-ONLY VERIFICATION NOTE: the fixes in this entry that live inline (safe-mode precedence, gamepad latch, watchdog grace, forget guard, deadzone rounding, radius guard, screen pages) are pinned by source review and compile validation; their hardware behavior remains bench-covered by the standing 4.8.x-5.0.0 wire sessions and needs the next live round for radio-visible confirmation. The pure-layer behaviors (serial RX framing, seed gate, hard-band classifier, host-switch decisions, TX-queue watermark) are host-pinned.

Version 5.0.0 | 2026-11-18
- THE FULL-BRANCH AUDIT CYCLE (review rounds over the entire codebase; upstream parity re-verified by fetch: the fork contains every upstream commit — upstream's latest release is V4.1/4.1.0, its main tip is an ancestor of this branch, so this release is a single step from 4.1.0 and the 4.2-4.9 line was the fork's own development path, not separate upstream releases). Version moves to 5.0.0 to mark the audited release line.
- HARD SIP/PUFF INPUTS (pressure classify, engage, and offset filters plus the /settings2.dat hard band): instant access to long-window actions for users who cannot sustain a 1-3 s hold, with hard thresholds enforced above the regular band so a regular puff can never fire a hard action.
- MULTI-HOST BLUETOOTH SWITCHING (upstream #16): independently switch between bonded Bluetooth hosts from the Hub menu or serial API, with the bench-driven switch window, bond-directory host table, and open-advertising handover with a device-side bouncer.
- HID-SUBSCRIPTION WATCHDOG: a bonded peer whose mouse-input CCCD is not enabled within a grace window gets its link disconnected once, so a "connected but HID-dead" host self-heals on its own retry.
- READ-TRUTH SETTINGS GETTERS: failed flash reads can no longer fabricate compiled defaults as SUCCESSful answers; getters answer the in-force value on a read failure.
- BOUNDED WIRE TRANSACTIONS: the boot scan is bounded-retry with a proactive bus-clear, the deliberate reset leaves the bus idle, and the vendored Wire gains a busClear() primitive — stranded I2C slaves no longer survive a warm reset into the next boot.
- BOOT-BUS FIX SET: the bus comes up at the top of setup() with a proactive bus-clear; checkI2C() probes up to 3 passes; softwareReset() quiesces every I2C-driving poll before farewell traffic and bus-clears at reset; the hardware safe-mode warning names the missing device set in the heartbeat's sns= encoding.
- RAIL SELF-MEASUREMENT: readVddMillivolts() samples the SAADC internal VDD channel and reports it as BH field 29 and on degraded heartbeat lines — diagnostic only, no behavior keys on it.
- BOOT-TIME ONE-SHOT DIAGNOSTICS: pre-attach diagnostics now reach the wire on the first host that opens the port via serialTxEnqueueDiagLine, instead of being silently dropped by the anti-replay gate.
- MENU/SERIAL RESET GUARD: softwareResetGate() waits the BLE-init window out bounded and refuses with a named ERROR line; the six serial endpoints gate before store/mutate/ack so a refusal answers FAIL,3 with nothing touched.
- FULL-BRANCH AUDIT FIXES: the latch guard no longer swallows the first hold on a host connected inside the poll gap; joystick corner capture seeds from the first valid reading so off-neutral units capture real corners; the serial overflow path answers once and swallows the rest of the frame; DM,1 refuses mid-flow; eight settings getters now apply read-truth; the SAP LED reset ceiling moves 8 s -> 60 s; internal-center aborts persist the chain's initiator; the >cap bond enumeration never evicts the active host; deadzone loads type-gate with is<float>(); every direct buzzer emitter clears the note queue first.
- RELEASE PIPELINE: build_firmware.yml (tag/dispatch-only, fail-closed gates: tracked source ZIP vs tree, tag<->LSConfig version equality, release assets + sha256 manifest, orphan firmware-binaries branch) and compress_firmware.yml (tracked source ZIP stays current via content-compare bot commits). Release-channel caveat: upstream has no firmware-binaries branch, so on merge day upstream's app-update channel starts empty and the first upstream V* tag creates it.
- VERIFICATION: host core suite 385/385 and timer suite 168/168 under ASan/UBSan; production compile clean at --warnings all (381884 B / 47% flash, 59196 B / 24% RAM, pinned core 1.1.13); the tracked source ZIP (189 files) verified tree-identical by the release gate's entry-content rule; dist/ regenerated from this exact tree — HEX, UF2 payload, and DFU .bin are one byte-identical image matching firmware-manifest.json; first hub session on the flashed 5.0.0 binary: 17/17 live wire test groups PASS.

Version 4.1.0 | 2025-March-31
- Software bug fixes and added features 
	- TinyUSB Library bug fixed, now works with latest version (3.4.2) of the library
	- Full calibration changes
		- Moved to "More" menu to prevent Full Calibration from being selected when not necessary
		- Added warning message and confirmation page
		- Added error checking, if joystick was not moved enough during full calibration, use default value instead
	- No USB auto mode switch fix
		- 4.0.1 added a feature that if no USB was detected the LipSync would automatically switch to Bluetooth mode, but this caused unintentional effects 
		- Now, if no USB is detected, the screen displays an error message and buzzer plays an error tone, but continues to try to connect in the background
		- To change modes, the menu can now be used even if no USB is mounted.
	- i2c error checking
	- Light Brightness can now be adjusted through Hub menu or API
	- Scroll speed can now be adjusted through Hub menu
	- Scroll is now calculated differently, at a higher poll rate but not performed every loop, depending on the scroll speed
	- Fixed bug where scroll speed was dependent on cursor speed
	- Fixed bug in timers, so timer offset now works properly
	- Deadzone changes
		- Outer deadzone has its own variable and is independent of inner deadzone
		- Output now starts at 0% at the end of the innder deadzone, and goes to 100% at the edge of the outer deadzone
	- Added additional sounds for startup, powering off, and errors
	- Added watchdog implementation
	- Added safe mode accessible by Hub Buttons, or triggered during hardware error or watchdog
- Hardware changes
	- Ribs were added to the screw bosses on the LipSync Hub Top and LipSync Hub Bottom to increase strength
	- LipSync Mouthpiece was simplified
		- The updated mouthpiece is comprised of the same hydrophobic syringe filter, a Luer adapter, and a large silicone straw. This simplified design is easier to assemble, easier to clean, and has the added benefit of reducing the overall cost.
- Documentation updates
	- Maker Guide
		- TinyUSB library - can now use latest version (3.4.2)
		- Added additional assembly step to test joystick components before assembly into Joystick Gimbal and housing
	- User Guide
		- Updated to reflect changes to menu structure and full calibration process
		- Expanded troubleshooting with error messages
	- Created LipSync Firmware Upgrade Guide
	- Created LipSync Information Sheet
